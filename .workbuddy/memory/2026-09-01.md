# 2026-09-01

## 项目启动：index-demo（Agent 场景检索引擎）

从空目录开始，通过两轮问答确认需求，产出 `docs/需求分析与设计.md`（v1.0）。

### 需求基线（问答确认，不可推翻）
- 定位：通用检索引擎内核，可插拔（索引+召回+融合+排序），场景层（知识库/记忆/代码）后接
- 语言：Rust
- v1 能力：BM25 + 向量语义 + 混合融合；Rerank 不在 v1，架构留位
- 形态：单机 MVP，万级文档
- 向量索引：先集成成熟 crate，抽象成 trait，后换自研
- Embedding：trait + 本地/远程双实现，feature flag，默认本地
- 分词：jieba-rs（中）+ 英文 tokenizer 混合
- BM25：完全手写倒排，不用 tantivy
- 持久化：内存索引 + 二进制快照
- 交付：库 + CLI + 示例中文语料

### 技术选型（已联网核实）
- `instant-distance` 0.6.1 纯 Rust HNSW，Apache-2.0，rayon 并行构建，with-serde 支持 bincode。**无增量插入 API**（最大限制）
- `fastembed` 5.17.4（ort/ONNX），支持 BAAI/bge-small-zh-v1.5（512 维）
- `jieba-rs`、`rayon`、`bincode 1.3`（与 instant-distance 内部版本对齐）
- 弃用：`arroy`（耦合 LMDB，与内存+快照路线冲突）、`tantivy`（BM25 要手写）

### 关键技术决策（踩坑点已写进文档）
1. **BGE 查询侧必须加 instruction 前缀**，入库侧不加 → `Embedder` 强制区分 `embed_query` / `embed_documents`。漏掉效果显著下降且极难自查
2. **向量入库前 L2 归一化**：归一化后 `cos = 1 - d²/2`，与 instant-distance 的距离语义单调等价；且内积 == 余弦
3. **增量写入**：主 HNSW + delta 暴力区，delta ≥ 1000 或总量 10% 时后台重建
4. **融合默认 RRF（k=60）**：两路量纲不可比（BM25 无上界 vs 余弦集中于 [0.6,0.95]），归一化既损失信息又不稳定（min-max 单候选时除零）
5. **中文 avgdl 偏小**（分词后 term 数少于英文），k1=1.2/b=0.75 只能当起点，P5 必须网格搜索重调
6. **BM25 用 OR 语义禁止 AND**：Agent query 含幻觉词时 AND 会导致整体零召回
7. 删除 chunk 时重新分析文本维护 df（而非维护反向映射），用 CPU 换内存
8. MVP 就存 posting positions，事后补需重建全索引
